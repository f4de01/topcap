# ADR 0003：纠错走云端兼容 API，纠错与分段拆成两次各带守卫的调用

日期：2026-10-04 · 状态：已接受

## 背景

转写直出的文案有同音错字、专有名词写错、没有段落。把它变成可读的成稿要动文字，
而本项目的硬指标是**完整文案**：不改写、不摘要、不删减。任何动文字的步骤都有"顺手改写"的风险，
而且改写后的文本更通顺，人读不出来。

最初设想是让调用 CLI 的 agent 自己改文案。否决的理由：一个主题十条内容就是三到五万字进出 agent
上下文；agent 的改动没有机器守卫可拦；博主库几十条时 agent 无法批量处理。

## 决策

1. 纠错和分段由 CLI 调用一个 **OpenAI 兼容的 chat API** 完成，`base_url` / `model` / `api_key`
   全部可配，默认指向 DeepSeek。ollama 也是兼容接口，填本地地址即是本地方案。
2. **纠错**和**分段**是两次独立调用，各带能真正执行的守卫：
   - 纠错按约 1200 字分块，某块改后长度变化超过 15% 即判为改写，丢弃该块回退原文。
   - 分段时模型**不输出正文**，只输出每个新段落开头的几个字作锚点，正文由代码在原文上切分。
     模型没有机会碰正文，"不改动任何字符"从事后校验变成结构性保证。
3. 没配 key 时降级为只做繁转简和空白清理，终端明确提示。agent 不碰文案。

## 理由

- 两步合成一次调用更省钱，但只剩长度阈值这一道近似守卫兜住全部风险。拆开后分段这一半变成零风险。
- 让模型输出分好段的全文再逐字校验，实测拦截率高到分段几乎失效：模型总会顺手修一两个标点。
  锚点法是唯一既让模型分段、又让它碰不到正文的办法。
- 费用不构成理由：一个主题约 10 万 token，几毛钱。

## 后果

- 用户要多配一个 key 才有纠错。接受：这是可选项，没 key 也能跑通。
- 每条内容多一次 LLM 往返。
- 原始文案始终落盘在工作目录，任何对成稿的怀疑都能回溯核对。
