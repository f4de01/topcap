# TopCap

命令行工具 `topcap`（`pip install topcap` 或 `uv tool install topcap` 装到 PATH 上）。
你的职责只有两件：**挑候选**、**转达闸门**。文案一个字不要碰。

## 流程

```
topcap search "<主题词 | 视频链接 | 博主主页 | 整段分享文案>"   # 列候选，不下载
     ↓ 你按主题相关性挑序号
topcap run "<库名>" --pick 1,3,5                                 # 取文案、纠错分段、写成稿
```

`search` 自己识别输入形态：没有链接就是主题词；视频链接进「收件箱」库（`--topic X` 可改库名）；
主页链接建 `@昵称` 博主库。**分享文案原样传进去，不要自己截 URL**，命令会把链接捞出来。

`run` 输出写到用户配置的知识库目录，每个库一个文件夹，一条内容一份 md，带 YAML frontmatter。

## 规则

1. **主题库：挑 3 到 12 条，按相关性，不凑数。** 搜索结果里多数条目与主题无关，不相关的不要放进去。
   同等相关性下优先挑短的。
2. **博主库：先列清单，问用户全要还是要部分，按用户说的跑。** 给主页链接的人多半想要全部，
   这时用 `--pick all`，不要按主题那套挑几条交差。
3. **时长带 ⚠ 的超过 20 分钟。** `run` 会拦下并报预计耗时（退出码 2）。转达用户，用户确认后才加
   `--allow-long`。不要自己加。
4. **B站有 CC 字幕时直接用字幕，几秒出稿；没有才本地转写。** 成稿 frontmatter 的
   `transcript_source` 标明来源。用户嫌某条字幕质量差，可以删掉成稿后用 `--no-subtitle` 重跑那条。
5. **同一个库可以多次 `search`，是追加不是覆盖**，已有序号不变。
6. **`✗` 是失败，`✓` 后面跟着黄色「注意」是降级。** 最常见的注意是「LLM 不可用」：成稿没纠错没分段，
   提醒用户检查 `~/.topcap/config.toml` 里的 LLM key。无语音的内容（纯音乐）会报失败，另挑一条补上。
7. **复筛在 Obsidian 里做。** 哪篇够用、哪篇要删，由人判断；你不要替用户删成稿。

## 首次使用

用户还没配置时，让用户在终端自己运行 `topcap init`（要输入 API key，交互式），
然后 `topcap doctor` 自检。模型约 165MB，首次会自动下载。

## 退出码

0 成功 · 1 错误（看 stderr） · 2 闸门拦下（需要用户确认后加参数重跑）
